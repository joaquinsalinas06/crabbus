# Decisions

| Decision | Rejected alternative | Why |
|---|---|---|
| Native `SendMessage` for master→agent messages | A file/`$.store` mailbox delivered through `tool.call` deny/result | Exp. A: SendMessage reaches a running background subagent at its next tool round and keeps its context. Injecting through `tool.call` would alter tool results. |
| Observe `session.send` / `session.receive` (pass-through) | Rewriting messages | Gives "accepted" and "delivered" without touching content. |
| `bus_step` tool + ~140-token brief on `agent.spawn` | Inferring plan/stages from transcripts | Progress must be declared by the agent; inferring it would invent numbers. |
| Three separate layers (observed/declared/verified) | One percentage | Required: 4/5 declared ≠ 80 % of the work. |
| Hand-drawn 18x14 sprites, half-block cells | Downscaling savvy-progress's 30x28 SVG crab (v0.1) | The downscale lost hats and props; half-blocks keep exact colors. |
| One `Raster` for the whole stage + `$.ui.blit` | Redraw on every tick via state | Fewer redraws; envelopes can fly across cards. |
| Cells only | `Image` (kitty/iTerm2) | Pixel art at native size is exact in cells; Image needs terminal support and a flag in iTerm2, and was not verified. |
| Extra agents counted in the master's label | A "+N" card | A card cost 19 columns and broke the 40-column layout (caught by a test). |
| English schema & identifiers with v0.4 legacy normalization (`src/legacy.ts`) | Hard break dropping Spanish v0.4 JSON / IDs | Existing `.json` designs, `/disfraz`, `.cangrejo.json`, and built-in IDs continue loading with 0 pixel diffs; `/costume migrate` upgrades files safely with `.bak` backups. |
| Permission asks are shown, not answered: `tool.check` → `ask` in a person-decides mode marks the agent blocked until the call runs | Approve/deny buttons in the panel (the v3 design) | Tried live (2026-10-13) through `tool.check` and `classic.PermissionRequest`: Claude Code shows its own dialog regardless and the call waits on it; a plugin's answer neither closes it nor runs the call. Buttons would pretend. In auto mode an `ask` goes to the classifier, so nothing is shown. |
| Per-agent usage from `turn.step` results; cost = usage × list price, shown with `≈` | Cost from `session.measure` deltas attributed to "the last agent that stepped" | No API gives a subagent's cost; deltas mis-attribute when agents run in parallel. The session total stays the ledger's real number. |
| Declared stages shown as `done/total` in METRICS | The design's `TASKS 57%` | A percentage of declared stages reads as % of the work, which the three-layer rule forbids. |
| Cards use the full 18x7 crab; rows and the half-size view use a 9x4 halving that keeps rare colors | Re-drawing every costume at small size | Halving keeps any costume (including users' designs) recognizable with no extra art. |
| Card backgrounds are neutral grays; the state's color is the border, chips use tints with every channel ≤ 25 | Tinted card backgrounds (the design's) | Claude Code may draw in 256 colors (it does inside tmux even with COLORTERM=truecolor): a gray lands on the gray ramp, a dark tint rounds to the cube's #5f5f5f (seen live). |
| List crabs are text (half blocks) inside Buttons, redrawn twice a second | Rasters repainted with `$.ui.blit` at the configured fps | A Raster cannot be pressed; the design asks for a press anywhere on a card. Two frames a second matches the design's stepped bob. The detail's crab stays a Raster. |
| Deterministic keyword classification (`src/kinds.ts`) evaluated at spawn time | Calling an external or local LLM/classifier during `onSpawn` | Preserves synchronous reducer purity (`model.ts:onSpawn` is strictly synchronous and fast). Offline, zero-cost, privacy-safe, with no machine or local network dependencies. |
| Crabs in the panel are `Raster`s repainted by the clock; their name and text rows are the press targets | Each half-block row of a crab as a `Button`, so the crab itself is pressable | Claude Code inverts a Button under the pointer, and an inverted half-block cell swaps its two colors: the crab's row showed upside down. A `Raster` takes no press yet, so the rows beside it carry the press, and the wardrobe card lights under the pointer. |
| The `spin` play keeps its 12 steps | More steps for a smoother turn | Shared designs time their own drawings to those steps (the dino shows its back on steps 3-7); a longer spin showed the back while facing front and failed the fit check. The turn looked choppy mainly because the master's crab was redrawn twice a second; it is now repainted every frame. |
| "Tell CrabBus" submits one prompt to Claude, only when the person presses Enter | Classifying requests with a local model, or editing rules from free text inside the plugin | Claude already has the design skill, the web and the files; the plugin only frames the request with what is set now. Nothing starts a turn on its own. |
| Asynchronous kind pre-resolution in `hooks/register.tsx` before reducer dispatch | Making the reducer async or deferring costume assignment | The state machine remains deterministic and synchronous. Pre-resolving kind asynchronously in the spawn hook allows future pluggable classifiers without breaking the event flow. |
| Attribution `by` formatted as `${rule.origin} #${rule.ruleIdx}` (e.g. `rules.json #2`, `(built-in) #6`) | Generic `"rule #N"` index or rule nickname | User rules prepend before built-ins; indexing into a combined list would make rule numbers change depending on user files. Recording the source file name and 1-based index is unambiguous and keeps nicknames unpolluted. |
| The wardrobe is a second view of the side panel, behind a tab row (`agents` · `wardrobe`) | A separate pane, or a button in the panel's header | One pane keeps one focus and one set of keys; a header button collided with the header's own facts. `/costume` opens the same view, and prints the rules as text where no panel can be drawn. |
| Dynamic `pack.active` inheritance in `rules-edit.ts` | Overwriting active rotation with hardcoded defaults | Toggling an active costume in the UI when `rules.json` lacks an explicit `active` list inherits all currently active costumes rather than resetting the rotation to built-in presets. |
| A rules edit is planned in memory (`src/rules-edit.ts`): only the files that carry rules are compiled again over the pack in use, then the change is shown and the file written | Validating with a full `loadPack` before every write | A full reload fit-checks every costume: about 590 ms on six user designs, during which the crabs stop. Rules never change a costume's pixels, so recompiling only the rules (0.3 ms) gives the same pack, which a spec checks against a full reload. A file that is not valid JSON, or a pattern the pack refuses, is never written; the edit is refused with the reason. |
| Body as data; crab kept pixel-identical | A renderer branch for each creature | One Pose interpreter draws editable body layers and anchors; existing golden fingerprints stay unchanged. |
| Each costume names its body; none means crab. `rules.defaultBody` is not read (a warning says so) | A crew-wide default body (`rules.defaultBody`) | People mix species by skin: crabs, robots and capybaras in one crew. A global default replaced every skin at once and made each costume's look depend on another file. |
| New creatures are drawn from scratch in their own view, with a body `color`, a fixed `palette` and pieces drawn for that body | Reshaping the crab grid with crab-relative anchors only | A capybara built on the crab's front view read as "a crab with ears" (tried live 2026-10-14). Its own silhouette, outline, muzzle and leg colors make it recognizable at 18x14; crab pieces still work where they fit, and held props follow the body's paw anchors. |
| Tell CrabBus makes a skin unless a new body is asked for in so many words | Guessing a new species from "a capybara costume" | The person's crabs with capybara hats are skins; a new creature is a bigger change they must ask for. |
| Built-in body choices save same-ID user costume overrides | Editing the installed built-in source | User changes persist without changing shared artwork or losing sibling bundle items. |
| Body selectors fit-check before enabling and again before saving | Accepting a selection then silently hiding incompatible pieces | The visible body/costume/action/tick reason explains what must be repaired; cached results last only for the current pack revision. |


## Unverified assumptions (what breaks if wrong)

- `session.receive` fires for every SendMessage delivery to a subagent (verified once in a real run; if it does not, "delivered" stays unset and only the declared ack shows).
- The band's `maxRows` is the only height limit (if not, the stage may scroll).
- `$.state` survives a hot reload (designed for, unverified); module timers restart on reload.
- `$.session.messages({ agentId, as: 'api' })` reads a running background subagent's transcript (if not, the detail falls back to the hooks' tool log).
